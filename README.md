# Foundry 本地模型部署控制台

本地版本：2026.09.30-targets-v2。

四步完成一批部署：**连接 SP → 目标与命名 → 选择模型 → 部署与结果**。网页连接的是同目录的真实部署脚本，不是模拟部署页面。只有最后确认「开始真实部署」才会创建或更新云资源。

## 1. 启动

1. 安装 Python 3.10 或更新版本；这份工作区已有可用的托管 Python，启动器会自动查找。
2. 双击本文件夹中的 **双击部署.cmd**，保留打开的服务窗口。
3. 浏览器进入 http://127.0.0.1:8765/。**不要直接双击 HTML**，直接打开文件不能调用后端。

更新代码后，先确认没有部署正在运行，再关闭旧服务窗口、重新双击启动器，并在浏览器按 Ctrl+F5。页面右上角可核对版本。

网页流程只使用 Python 标准库，不需要 Azure CLI、azd，也不需要先安装 openpyxl。若启动器找不到 Python，可以设置环境变量 FOUNDRY_PYTHON 为 python.exe 的完整路径。

> 此版本只监听本机 127.0.0.1，不是公网多用户服务。没有访问登录保护时，不要把端口直接开放到公网。需要给别人使用时，复制正式代码和启动器，让对方在自己的电脑启动；不要携带你的凭据和历史 output。

## 2. 连接 Azure

将客户提供的 SP 粘贴到页面，例如：

~~~text
APP_ID=应用程序客户端ID
PASSWORD=客户端密码的值
TENANT_ID=租户ID
~~~

也支持 AZURE_CLIENT_ID、AZURE_CLIENT_SECRET、AZURE_TENANT_ID，以及包含这些字段的 JSON。可以点击「识别填写」检查，或者直接连接；密码以掩码显示。

连接后读取该 SP 可见的订阅，后面的订阅从下拉列表选择，不必重复输入。只有一个订阅时自动填入目标。**能登录不等于具有创建资源、读取模型目录或删除资源的权限**；读取失败会显示错误，不会当作“没有资源”。

网页不读取 foundry.local.json 里的旧凭据。它为空不影响网页流程；直接在网页填写即可。

## 3. 目标与命名

### 标准部署

适合一个订阅、一个区域，批量部署多个模型。

- 选择订阅和部署区域。
- **新建资源组**：填写资源组名称，也可以使用命名拼接工具添加前缀、区域、序号和后缀。
- **使用已有资源组**：读取后选择即可，不再要求填写新资源组名称。
- 设置 **Project 名称**。
- 系统自动生成 Foundry 资源名，页面展示最终名称预览。

### 自定义部署

在标准部署基础上，可以添加多个目标，并分别设置订阅、区域、资源组、Foundry 和 Project；还可以自定义模型部署名称、版本、SKU、容量。

| 场景 | 选择方式 |
| --- | --- |
| 没有资源组 | 新建资源组 → 新建 Foundry → 新建 Project |
| 已有空资源组 | 使用已有资源组 → 新建 Foundry → 新建 Project |
| 已有资源组，已有 Foundry | 使用已有资源组 → 使用已有 Foundry → 新建或使用已有 Project |
| 读取到资源组，但不想使用 | 保持/切换“新建资源组”，填写新名称 |

已有资源组不必包含 Foundry 才能使用。资源组的管理位置不用于限制新建 Foundry 的部署区域；选择已有 Foundry 时，部署区域锁定为该 Foundry 的实际区域。

选择已有 Project 后不再输入新名称。切换来源时会保留新建名称草稿，但不会把上一资源组的 Foundry 或上一 Foundry 的 Project 错带入新目标。

**Project 名称和模型部署名称是两个不同字段。** Project 在目标页设置，模型部署名称默认使用模型名称，不追加区域或序号；自定义模式可以修改。不能在同一个 Foundry 下用相同的部署名称创建两个不同任务，即使选择了不同 Project。

## 4. 选择模型：不会自动倍增

模型目录按目标订阅和区域读取，**不需要先创建或选择已有资源组**。使用已有 Foundry 时读取其模型目录。可按名称搜索、按发布方和目标筛选；读取过程有加载状态和错误重试。

目录显示的是当前部署接口返回并具有受支持 SKU 的模型，不是承诺支持市面上所有模型。目录中存在也不代表配额、地区容量或订阅权限一定满足，实际结果以部署返回为准。

**一个勾选的模型默认生成一条任务。** 多个目标下，系统从支持该模型的目标中优先选择任务较少的目标；任务行可以重新指定目标。

例如：

| 任务 | 模型 | 目标区域 |
| --- | --- | --- |
| 1 | 模型 A | eastus |
| 2 | 模型 B | westus3 |

以上共 **2 条任务**，不会因为两个区域而变成 4 条。要把同一个模型部署到多个区域，请明确复制该任务，再选择目标；只有你明确添加的任务才进入计划。

可调整的容量单位以模型/SKU 目录为准，页面校验最小值、最大值和步长。OpenAI 模型的内容防护开关对应工具内的最低过滤配置/加强防护配置，**不表示关闭 Azure 平台的全部安全机制**；其它模型使用其平台支持的默认配置。

## 5. 确认、部署与结果

1. 检查最终任务表：模型、版本、SKU、容量、订阅、区域、资源组、Foundry、Project 和模型部署名称。
2. 可选：点击 **只读预检**，验证输入和目标资源的存在性、兼容性，展示哪些资源复用、哪些将新建。预检不创建资源，也不是完整配额保证。
3. SP 已连接且计划完整时，**开始真实部署**即可点击，无需先手动预检。提交时重新校验当前计划，并在确认后由后端复查目标。
4. 查看每条任务的真实执行阶段，以及成功、失败/未完成、执行中数量。
5. 展开 JSON 和日志，或下载报告。

自定义模式中的执行选项：

- **自动注册 CognitiveServices Provider**：部署脚本在需要时注册资源提供程序；不是创建额外模型，也不会替 SP 自动增加权限。
- **允许更新配置不同的同名模型部署**：默认关闭，避免覆盖已有部署。相同配置可复用，配置不同会给出错误；明确开启后才允许更新。
- **无法读取配额时交由 Azure 校验**：不绕过平台限制，只让请求交给 Azure 最终校验。
- **并发资源组数**：1–4，默认 2。不同资源组/订阅可并行，同一资源组内顺序执行，避免同时创建相同资源。并发不会增加计划行数。

### 报告

每次运行在本文件夹的 output 中保存一套同名报告，例如：

~~~text
results_2026-09-30_113000_123456_批次ID.csv
results_2026-09-30_113000_123456_批次ID.json
results_2026-09-30_113000_123456_批次ID.xlsx
~~~

日期使用运行开始时本机的本地日期；时间和批次 ID 防止同一天重复运行互相覆盖。运行过程中更新同一套文件，不额外生成第二套结果目录；历史批次仍保留。CSV/JSON 各一份，XLSX 是便于阅读的同批 Excel。

报告保留订阅、区域、资源组、Foundry、Project、模型、部署名、Endpoint、状态和错误等字段。当前网页流程**不读取或导出资源 API Key**，密钥列为空；SP 密码和访问令牌不写入结果。

成功包括 created / updated / unchanged。没有最终回执的正在执行任务标为 interrupted（状态待核实），尚未开始的标为 not_run；不会假报成功。正常进程收尾时报告会补齐所有计划行，与页面统计一致。

「仅重试失败任务」保留失败和未执行条目，排除已成功条目；状态待核实的 interrupted 不自动重试，先确认云端状态再决定是否重新部署。重试会生成新的批次报告。

### 刷新、中断与重启

- 服务运行期间，刷新页面可读取最近一批执行状态；页面中的 SP 和未提交草稿不会持久化，需要重新填写。
- 正在部署或等待提交回执时，页面锁定关键输入，防止重复提交。
- 网络超时时先刷新状态，系统会查询该请求的提交回执；不要重新点击生成另一批。
- 服务重启后不恢复内存任务、SP 和草稿。历史文件仍在 output；不要把服务重启当作云端任务取消。强制结束进程或断电时可能来不及补全最终报告，应先核实云端资源。

## 6. 资源管理与安全

资源组删除位于独立「资源管理」弹窗，不与正常部署操作混在一起。先预览其中资源，再输入完整资源组名并二次确认。删除会影响组内全部资源；本工具不能撤销。

SP 在浏览器/进程内存中使用；真实执行时通过系统临时目录中的一次性 JSON 传给子进程，正常结束清理，不写入项目配置。异常强制终止可能留下系统临时文件，应按敏感文件处理。共用电脑不要让不可信用户访问运行中的服务、临时目录或历史报告。分享项目时移除真实 foundry.local.json 和 output 内容；已经对外公开的 Client Secret 应轮换。

## 7. 目录与兼容入口

- Foundry部署控制台.html / foundry_console.css：正式界面与布局。
- foundry_console.js / foundry_plan.js：页面控制、目标和任务分配。
- foundry_web.py：本地服务、查询、预检、任务进度与下载。
- foundry_plan.py：后端计划校验；拒绝重复和不兼容目标。
- deploy_foundry.py / run_foundry.py：真实部署执行。
- foundry_results.py / foundry_details.py / foundry_excel.py / foundry_regions.py：报告、详情和兼容辅助模块。
- 双击部署.cmd：启动器。
- output：运行报告；不会自动删除历史结果。

原 Excel 模板、foundry.local.json 和 requirements.txt 保留给兼容的命令行入口，不是网页必填项。若使用 Excel 入口，需要其依赖，并由操作者在 JSON 中填写 SP、在 Excel 中填写计划。不要把网页临时计划和旧 Excel 同时作为一次运行的输入。

## 本次本地校验范围

做了 Python/JavaScript 语法、离线计划/报告回归、JSON dry-run 和隔离的浏览器流程检查。没有使用真实 SP，没有连接客户网站，也没有执行 Azure 部署或删除。权限、配额、实时区域容量及云端响应仍需由实际操作者验证。

### 配额无法读取时

确认页直接显示 **配额读取失败时仍尝试部署**。默认关闭；明确勾选后，仅对配额无法核实或配额接口 HTTP 401/403/404 的情况继续，由 Azure 创建接口最终校验。已读取到配额且不足时仍停止；不会绕过部署权限、模型供应限制或真实配额。配额项缺失不能直接判定 SP 无效。失败批次可以选择“仅重试失败项”，核对目标后再提交；成功项不加入重试。
