# Foundry 本地模型部署控制台

本地版本：**2026.10.10-customer-v3**。

五个独立页面：**连接 Azure → 部署模式与目标 → 共同命名 → 选择模型 → 部署与结果**。

这是连接真实部署脚本的本地控制台，不是模拟页面。正常部署流程只有在最后确认“开始真实部署”后才会创建或更新云资源；资源删除另有独立确认。读取目录、编辑计划和只读预检不会创建资源。

## 1. 启动与更新

1. 准备 Python 3.10 或更新版本。当前工作区已有托管 Python，启动器会自动查找。
2. 双击本目录的 **双击部署.cmd**，保留服务窗口。
3. 浏览器打开 **http://127.0.0.1:8765/**。不要直接双击 HTML；文件方式无法调用后端。
4. 更新代码后，先确认没有运行中或待核实的批次，再关闭旧服务窗口、重新启动，并按 **Ctrl+F5** 刷新页面。右上角显示版本。

网页入口只使用 Python 标准库，不需要 Azure CLI、azd 或 openpyxl。启动器找不到 Python 时，可把环境变量 FOUNDRY_PYTHON 设置为 python.exe 的完整路径。

> 仅监听本机 127.0.0.1。当前版本没有用户登录、租户隔离或 HTTPS 网关，不是公网多用户服务。不要直接映射到公网，也不要多位客户共用一个正在运行的实例。

## 2. 第一步：连接 SP，读取订阅

粘贴客户提供的服务主体，例如以下占位格式：

~~~text
APP_ID=<应用程序客户端 ID>
PASSWORD=<客户端密码的值>
TENANT_ID=<Microsoft Entra 租户 ID>
~~~

也支持 AZURE_CLIENT_ID、AZURE_CLIENT_SECRET、AZURE_TENANT_ID 和对应 JSON。点击“识别填写”或直接连接；识别后清空原始粘贴区，密码以掩码显示。

连接后从可访问的订阅列表选择，不必重复输入订阅 ID。网页不读取 foundry.local.json 中的旧凭据；该文件为空不影响网页操作。

认证成功不等于有部署权限。订阅、资源组或模型目录读取失败会保留具体错误，不会当作“没有资源”。查询失败时检查目标订阅、SP 权限和网络，不要为了绕过错误盲目创建另一套同名资源。

## 3. 第二步：标准 / 自定义目标

两种模式只负责选择目标和资源来源；命名放在下一页，共用后续模型选择、并发和结果流程。

| 模式 | 适用场景 | 操作方式 |
| --- | --- | --- |
| 标准部署 | 一个订阅，多区域、多模型 | 选择订阅，搜索并多选区域；需要复用资源时展开“逐区域资源设置” |
| 自定义部署 | 多订阅、同区域多个目标、已有 Foundry / Project 等 | 添加独立目标，逐个设置订阅、区域和资源来源；可移除最后一个目标 |

区域代码为主标题，中文区域名称作为下方提示。已选区域标签和目标数量帮助核对遗漏。

### 资源来源的三条路径

| 客户情况 | 资源组 | Foundry | Project |
| --- | --- | --- | --- |
| 尚无资源组 | 新建 | 新建 | 新建 |
| 在已有资源组中创建 Foundry | 读取并选择已有资源组 | 新建 | 新建 |
| 在已有 Foundry 中追加模型 | 选择其已有资源组 | 读取并选择已有 Foundry | 新建，或选择已有 Project |

- 读取到已有资源组，不代表必须使用；可以选择“新建”。
- 已有资源组不需要先包含 Foundry。它的管理位置不限制新建 Foundry 的部署区域。
- 使用已有 Foundry 时，目标区域固定为该 Foundry 的实际区域。
- 已有名称在命名页只读，无需再次填写。切换来源保留新建名称草稿，但会清除不属于当前父资源的 Foundry / Project 选择。
- 标准模式不会把同订阅、同区域的多个独立目标静默合并；此类计划继续用自定义模式。
- 移除含模型任务的区域或目标需要确认，仅移除当前计划，不删除云端资源。

每批支持 **1–20 个实际部署目标、1–100 条模型任务**。同一控制台同时只执行一个批次，批次内部支持模型并发。

## 4. 第三步：共同命名

填写一次“客户前缀 / 业务名称 / 起始编号”，可选后缀和编号格式；下方逐目标显示最终名称，提示紧跟在对应输入框下。

| 对象 | 自动命名规则 | 示例（前缀 acme，业务名 service，编号格式 01） |
| --- | --- | --- |
| 资源组 | 前缀-业务名-编号-后缀 | acme-service-01 |
| Foundry | 资源组名-区域，使用规范化名称 | acme-service-01-eastus2 |
| Project | Foundry 名-project | acme-service-01-eastus2-project |
| 模型部署 | 默认模型原名，不拼接区域或编号 | 与选择的模型名称相同 |

**Project 是 Foundry 项目名，不是模型部署名。** 模型部署名在选择模型页调整。

命名行为：

- 自动编号 = 起始编号 + 目标的命名组编号 − 1。相同订阅下，相同命名组编号可生成相同资源组名；Foundry 仍区分区域。
- 编号跟随目标保存；移除目标不重排已有编号，新目标不复用已移除目标的编号。
- 自动名称在相同输入下保持一致。过长的自动 Foundry / Project 名使用稳定摘要缩短，不加随机尾号。
- 手动改过的名称不被模板刷新覆盖。手动名称无效时显示错误，不会静默截断或改名。
- “恢复新建项的自动命名”仅重置当前目标的新建名称，不会改已有资源名称。
- 没有新建资源组时隐藏无关模板与编号；全部使用已有资源时不显示重置按钮。
- “查看命名 JSON”只展示命名结果，不含 SP。

命名预览不是云端名称可用性承诺。同名冲突不会自动改成另一名称；需要检查后自行调整。自动缩短后的潜在重复也会在计划校验中拦截。

## 5. 第四步：选模型，明确对应区域

模型目录按订阅和区域读取，**不需要先创建资源组**；使用已有 Foundry 时读取该资源的目录。支持搜索、发布方 / 目标筛选以及全部或部分区域支持筛选。读取时显示加载状态，失败可重试。

对每个模型直接勾选要部署的区域 / 目标，也可“全选可用区域”。**只有明确勾选的组合生成任务，不会自动计算所有模型 × 所有区域。**

| 需求 | 勾选关系 | 实际任务数 |
| --- | --- | --- |
| 一个模型部署五个区域 | A → 五个指定区域 | 5 |
| 两个模型分别部署两个区域 | A → eastus2；B → westus3 | 2 |
| 三个模型部署同一区域 | A、B、C → eastus2 | 3 |
| 混合部署 | A → eastus2、westus3；B → eastus2 | 3 |

只选区域、未分配任何模型的目标不会进入执行计划或创建资源。区域过滤器只过滤展示，不改变已选任务。

每条任务保留自己的版本、SKU、容量、部署名称和内容防护设置。目录刷新后不再支持的组合会标为待修正，不会悄悄换模型、版本、SKU 或区域。同一 Foundry 下不能出现两个相同部署名称的任务，**即使它们选择了不同 Project**。

目录可见仅代表当前接口返回了该模型及支持的部署规格，不代表任意订阅有权限、配额或实时容量。Marketplace 协议、模型准入或其他授权要求不会由本工具自动接受。

## 6. 第五步：确认、并发和执行

先核对确认表中的模型、订阅、区域、资源来源、最终名称、版本、SKU、容量和任务数；可选“只读预检”核对现有资源的存在性、类型和区域。

提交时冻结当前计划和执行选项。预览、执行和导出通过同一计划摘要关联，修改后的计划必须重新确认；不会按过期预览执行。

### 执行选项

- **模型并发数：默认 3，可选 1–8。** 不是只并发不同订阅：共享资源准备完成后，同一 Foundry 下的不同模型也可并发提交和等待。共享资源及配额预留受锁保护；实际速度仍受 Azure 响应和限流影响。
- **自动注册 CognitiveServices Provider：默认开启。** 仅在真实执行阶段按需要注册该资源提供程序；SP 仍须具备相应权限。不是创建 SP 或自动授予 RBAC 权限。
- **允许更新配置不同的同名模型部署：默认关闭。** 相同且一致的部署可复用；不一致则停止并说明，不静默覆盖。确需更新时由操作者明确开启。
- **配额读取失败时仍尝试部署：默认关闭。** 显式开启后，对受支持的配额不可读取 / 无法核实情况交由 Azure 创建接口最终校验；已确认配额不足仍停止。模型目录未提供稳定的配额标识时，本地无法映射配额池，会记录提示并交由 Azure 校验，不按模型名猜算余额。
- **内容防护**在模型任务中设置。降低防护不是保证关闭所有安全检查，也不会自动申请特殊权限；策略不受支持或同名策略配置不同会报错，不擅自覆盖已有策略。

最后点击“开始真实部署”，核对确认框后才执行。正在提交、执行或等待核实时锁定关键输入，避免重复提交。资源创建和模型使用可能产生费用。

不会自动做：删除 / 回滚云资源、释放其他部署配额、分配权限、接受 Marketplace 条款或发起模型推理测试。

## 7. 结果和导出

结果页显示 **总任务、成功、失败、未执行、待核实、执行中、排队** 七项计数，提供进度、逐模型状态、日志和 JSON 展开查看。

正常写入时，每批在 output 中保留 **一份 CSV + 一份 JSON**，同批使用同一个文件名前缀，例如：

~~~text
results_2026-10-10_143025_123456_<批次标识>.csv
results_2026-10-10_143025_123456_<批次标识>.json
~~~

日期与时间取本机批次开始时间；跨日结束仍沿用同一批次文件名。进度更新替换同批文件，不额外生成无日期副本；新的部署或重试使用新批次，历史批次不会自动删除。**网页不再生成 XLSX。**

报告包含订阅、区域、资源组、Foundry、Project、模型、部署名、版本 / SKU / 容量、Endpoint、状态和错误等 22 列。JSON 额外保留批次 ID、计划摘要和结果计数。网页不读取或导出资源 API Key，兼容列“密钥”留空；SP 密码与访问令牌不进入导出文件。

| 状态 | 含义 / 处理 |
| --- | --- |
| created / updated / unchanged | 成功：新建、更新或配置一致的已有部署 |
| failed / auth_failed / config_failed | 已知失败，按错误修正后再提交 |
| not_run | 未执行，不等于创建失败 |
| interrupted / unknown | 结果待核实：请求可能已到达云端，不能假定失败或自动重试 |
| starting / running / pending | 启动、执行或排队中，不是最终成功 |
| planned | 兼容命令行的离线预览，没有部署资源 |

“仅重试失败项”生成包含失败 / 未执行任务的新计划，排除成功和待核实任务，需重新核对并确认。部署成功仅表示管理面结果已核对；**没有进行推理验证**，JSON 的 inference_verification 为 not_performed。

## 8. 网络中断、刷新与恢复

系统保守区分“明确拒绝”和“写入结果未知”：写请求超时、连接中断、无法解析回执或服务端 5xx，可能发生在云端接受之后，不会直接重复发送。明确的限流 / 认证拒绝可以按专门规则等待或刷新认证后重试；读取请求使用独立重试策略。

- **浏览器刷新**：可读取最近一个批次；SP 和未提交草稿不持久化，需要重新填写。浏览器 sessionStorage 只保存待确认请求 ID，不保存密码或计划。
- **提交回执暂未收到**：先“刷新状态”，等待本地接收记录；不要另起批次。相同请求 ID 不会重复启动部署。
- **服务重启 / 断电**：从 .foundry-state 恢复最近批次与接收记录，不恢复凭据或自动继续执行。能确认尚未交给部署子进程的任务标记未执行；可能已经交付的任务进入待核实和恢复锁定。
- **已核实，结束待确认提交**：人工确认原请求和云端状态后，结束本地等待并将请求标记为不可重放；不是取消 Azure 操作。
- **已核实云端状态，解除锁定**：人工确认后记录处理结果。旧部署进程仍在运行时不能解锁；待核实任务不会被自动改为失败或成功，也不会自动重试。
- **日志 / 状态文件损坏，磁盘或报告写入失败**：保留恢复锁定，先修复存储并核实云端。不要删除 .foundry-state 来强行跳过锁定。

关闭网页、停止服务或解除本地锁定都不等于取消已经提交给 Azure 的请求。自动恢复不做删除、回滚或补发写请求。

## 9. 资源管理与安全

资源组删除位于独立“资源管理”弹窗：读取资源 → 预览删除范围 → 输入完整资源组名 → 再次确认。删除会影响该组内全部资源，工具不能撤销。部署计划中的“移除目标”与云端资源删除是两件不同的事。

网页 SP 只在浏览器和进程内存中使用；执行时经 **stdin 管道**传给子进程，不写入临时凭据 JSON、项目配置、命令行或部署日志。.foundry-state 保存必要的批次 / 计划 / 回执元数据，但不保存 SP 或访问令牌。

运行机器仍须可信：其他本地进程或共享用户可能访问服务、内存或报告；脱敏不等于多租户隔离。output 和 .foundry-state 仍包含客户资源信息，请限制文件访问。不要将真实配置、状态或结果提交到 GitHub；已公开的 Client Secret 应由持有人轮换。

给他人使用时，复制正式代码和启动器，让对方在自己的电脑启动并填自己的 SP。**不要复制你的 foundry.local.json、output 或 .foundry-state**。需要集中提供客户服务时，须先另行设计登录、HTTPS、会话 / 租户隔离、权限与审计，不能直接开放当前端口。

## 10. 文件和兼容入口

| 文件 | 作用 |
| --- | --- |
| 双击部署.cmd | 查找 Python 并启动网页服务 |
| Foundry部署控制台.html / foundry_console.css | 正式页面与样式 |
| foundry_console.js / foundry_plan.js | 五步流程、命名、模型与目标分配 |
| foundry_web.py | 本地 HTTP 服务、查询、预检、批次与恢复管理 |
| foundry_plan.py | 后端计划规范化、名称 / 重复校验和计划摘要 |
| run_foundry.py / deploy_foundry.py | 真实部署执行入口和 Azure 管理接口调用 |
| foundry_results.py / foundry_details.py | 脱敏报告与资源详情 |
| foundry_regions.py / foundry_excel.py | 区域与兼容表格辅助 |
| output / .foundry-state | 运行结果与恢复记录，由真实运行生成 |

Foundry部署模板.xlsx、requirements.txt 和 foundry.local.json 属于兼容命令行流程，不是网页必填项。Excel 入口需要读取 .xlsx 的依赖，并由操作者在 JSON 中填凭据、Excel 中填计划；该入口可额外生成 XLSX。不要把旧 Excel 计划与网页提交混为同一次运行。

## 本次修改的验证边界

本次只做本地修改与离线验证：Python / JavaScript 语法、计划与报告回归、请求和恢复状态机，以及隔离浏览器中的前端交互检查。检查使用合成数据和内存中的模拟响应，不使用真实 SP，不访问客户网站，不进行 Azure 部署、删除或推理调用。

最终权限、模型准入、配额、实时区域容量以及云端实际创建结果，由操作者在自己的订阅上验证。
